# تقرير اعتمادية الشبكة وoffline

## الدعم الظاهر في الكود

- Service Worker يسجل من صفحة آمنة، ويخزن ملفات static وصفحات عامة سبق تحميلها؛ لا يضع الصفحات الخاصة في cache العامة.
- الصفحات العامة السابقة يمكن عرضها من cache، مع offline fallback عند فقد الصفحة.
- checkout draft (الاسم، البريد، الهاتف، البلد، المدينة، العنوان، الملاحظات) والسلة يحفظان في localStorage وفق guest/user scope.
- تغييرات السلة offline تسجل snapshot/revision ثم ترسل إلى POST /cart/recover بعد عودة الشبكة أو عند زيارة لاحقة. الخادم يتحقق من المنتجات والمخزون قبل استعادة cart.
- إرسال order offline يُمنع ولا يعاد إرساله تلقائياً؛ هذا يمنع تكرار إنشاء الطلب والثقة بسعر/مخزون مخزن في العميل.
- صفحة تأكيد الطلب تمسح cart/token/draft المحلية. الحد الأقصى السابق للكاش 30 صفحة و100 أصل ثابت. التخزين IndexedDB غير مستخدم.

## نتائج التحقق

- Feature tests لمزامنة offline cart موجودة ونجحت ضمن Pest: 83 test و430 assertions للمجموعة كلها.
- فحوص syntax لـ service worker وoffline reconnect نجحت.
- لم ينفذ browser E2E لفصل الشبكة أو التقاط screenshots لأن Playwright غير مثبت. لذلك لا أعتبر التصفح الفعلي بعد refresh/إغلاق browser متحققاً.

## سيناريوهات ما زالت غير مختبرة

فصل الشبكة أثناء تحميل صفحة لم تزرها، فتح product مخزنة، استعادة حقول checkout بعد refresh وإغلاق المتصفح، add/remove/update للسلة ثم reconcile، محاولة إرسال الطلب offline، عودة الشبكة مع تبويب مفتوح أو بعد إعادة فتحه، واستجابات 419/429/500 للمزامنة.

لا توجد blind retries لإنشاء الطلب. بيانات checkout المحلية بيانات شخصية؛ نظفها بعد إتمام الطلب وراجع أثر الجهاز المشترك.
